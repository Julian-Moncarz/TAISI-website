# TAISI website (taisi.ca)

A static site: plain HTML, CSS and JS, with no build step. Vercel serves the files as they are (`vercel.json` sets `framework: null`) and runs the functions in `api/`.

## Layout
- Pages: `index.html` (home), `programming/`, `resources/`, `team/`, and the forms `interest/` (fellowship), `interest/mentorship/`, `membership/`.
- `assets/site.css` holds the whole design system (tokens in `:root`). `assets/site.js` handles the nav, the Luma events feed, the mailing list and every form (`form[data-form]`). `assets/finder.js` is the Resources path-finder.
- Watercolour art is generated by `tools/make_*.py` (washes, skyline, shards in `assets/shards/`). The `wash-*.svg` card washes run off their own edges, so only use them inside a box with `overflow: hidden`; use `wash-portrait-*.svg` anywhere else.
- Brand files at the root (`logo.png`, `taisi-mark*.svg`, `taisi-wordmark*.svg`) keep the URLs the old site had. Other things may link to them.

## Functions (`api/`)
- `events.js`: the Luma calendar feed. Private events are listed by slug in `PRIVATE_EVENTS`.
- `subscribe.js`: mailing list, in the "mailing list" Airtable base.
- `interest.js`: fellowship and research-mentorship interest, in the F26 Intro base, "Expression of Interest" table.
- `membership.js`: membership applications, in the F26 Intro base, "Membership Applications" table.
- `discord.js`: redirects to the Discord invite, so the invite never appears in the page source.
- `_airtable.js`: shared helpers. Files starting with `_` are not routes.
- All of them need `AIRTABLE_PAT` in the Vercel environment. `tools/setup_airtable.mjs` creates any missing Airtable tables or fields; it's safe to re-run.

## Local development
`npm run dev` (or `tools\dev.cmd 4321` on Windows) serves the site and runs `api/` on http://localhost:4321, with no dependencies. Put `AIRTABLE_PAT=...` in a `.env.local`. It is gitignored, and the dev server deliberately ignores any `SMTP_*` keys, so a local server can never send real email.
